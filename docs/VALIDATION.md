## 自动化测试覆盖

### 文献与访问控制

- 使用实际 PDF、SQLite、本地 Qdrant 与 API 接口验证文献处理；测试中的向量与重排模型使用模拟实现。
- 覆盖访问令牌校验、文献用户隔离、检索范围、引用编号检查与空证据行为。
- 验证 PDF 文件与原文来源数据的对应关系，不以自动化通过数量代替问答质量评价。

### 流式问答

- 检查输出预算、推理选项与流式参数的请求构造，以及两种 token 参数的互斥处理。
- 覆盖长度终止、上游连接中断、缺失结束标记、只有思考而无正文等异常状态。
- 验证不完整回答中的正文保留与引用校验，未知引用编号被拒绝。
- 覆盖 401、403、404、429、500 等上游错误，不向客户端返回平台密钥或模型内部思考正文。
- 前端测试覆盖中文 UTF-8 分片、末行无换行、流内错误、提前 EOF、空闲超时和断开连接。

### 图片任务

- 验证模型 ID、接口地址、认证头、单张 2K、关闭组图、Base64 返回及水印参数。
- 覆盖平台错误、超时、非法 Base64、缺失图片和返回外部 URL 等响应。
- 验证相同请求编号的任务复用、不同参数冲突、并发上限与不自动重试行为。
- 验证草稿、任务、详情与文件下载的用户隔离；使用测试数据库和文件系统检查保存及重新打开后的读取。
- 验证未配置图片模型时文献问答仍可工作，空检索结果不触发配图描述生成。

### 论文翻译

- 从真实 PDF 提取整页原文，验证长页面分段后字符不丢失、不重复；不通过检索片段假冒全文。
- 验证目标语言与独立输出预算、译文结束标记、长度截断及未完整响应的拒绝处理。
- 验证完整页面持久化、重启后读取、同页同语言同模型的缓存复用，以及切换语言/模型后的重新翻译。
- 验证页码边界、空文本页跳过、全空范围的 OCR 提示；部分失败和第二段失败时不把该页保存为完整译文。
- 验证请求幂等、参数冲突、单用户任务上限、停止后续处理；失败后手动重试只复用已完成页面。
- 验证原文、任务、导出和停止接口的用户隔离；翻译中删除论文后不恢复记录或缓存。
- 验证 UTF-8 BOM 双语导出、未完成页标记；前端请求保留 UUID、语言与范围，通过认证请求取得导出 Blob。

### 阅读进度

- 验证旧库自动新增阅读表、原文和检索索引保留、记录跨重启恢复、重复上传保留记录。
- 验证上次页码与最远页码分开保存、往回翻阅不降低位置进度、最后一页不自动标记已读、明确重置待读。
- 验证读写认证、不同用户隔离、页码与状态校验、文献删除的外键级联及已删除文献拒绝写入。
- 前端测试覆盖状态与名称联合筛选、快速翻页合并、请求顺序、失败保留最新位置，以及保存结束和下一次翻页相邻的时序。
- 本次再次尝试 Chromium 浏览器启动，仍遇到 `socket() failed: Operation not permitted`。没有将单元测试和构建当成浏览器验收。

### 阅读进度本机验收

1. 启动 v0.6.0，在左侧“我的文献”找到“阅读进度”，已有论文应显示待读。
2. 打开一篇至少 3 页的论文，翻到第 3 页，等显示“已保存”，再返回第 1 页。关闭后卡片应显示上次第 1 页、最远第 3 页。
3. 点击继续阅读，应打开第 1 页；重启前后端并重新连接，进度仍应保留。
4. 手动标记已读并切换已读筛选，再改为在读；使用“记录页码”保存外部阅读位置。
5. 改为待读时先取消，确认进度不变；再次确认重置，检查页码归零且论文与译文仍存在。
6. 在测试论文中断开后端再翻页，应显示保存失败；恢复后重试。删除测试论文后阅读记录应同步消失。

### 翻译本机验收步骤

1. 启动前后端，连接知识库，上传两页以上的文字型论文。
2. 在列表点击“翻译”，选择简体中文及 1–2 页，检查原文预览、完成页数与逐页对照。
3. 导出 TXT，确认中文、论文名、页码、原译文与状态完整；换一页检查“复制”。
4. 关闭再打开窗口，查看翻译记录；再次提交相同页码，确认显示复用页数。
5. 打开 PDF 翻到第 2 页，点击“翻译当前页”，确认起始与结束页均为 2；切换英语目标并测试。
6. 在较长任务中停止后续翻译，确认保留完整页面；对扫描页检查 OCR 提示。删除测试论文后，其翻译记录不应继续出现。
7. 在电脑与窄屏窗口检查滚动、按钮和双语文本。保留一次真实翻译的平台记录，人工抽查术语、数字、公式与引用编号；不要将模拟测试结果当成翻译质量评分。

## 复现方法

项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m pytest -q
cd frontend
npm ci
npm test
npm run build
```

自动化测试不调用真实收费模型。`requirements-tested.txt` 是历史测试环境记录，不是完整依赖锁文件；运行环境安装入口为 `requirements.txt`。已记录的 Starlette/httpx 弃用警告不影响上述测试完成。

## 验证边界

- HTTP Mock 测试不能证明真实账号权限、平台额度、网络稳定性或模型输出质量。
- 文本请求预算的测试只验证字段构造，没有验证真实模型的最大上下文、最大输出或超长回答质量。
- 未完成真实浏览器端到端自动化测试；输入框恢复的历史检查来自代码审查及 TypeScript 构建。
- 尚无固定人工标注问答集的召回率、引用支持率或基线对照结果，也没有公网可用性与并发压力测试结果。
- 纯扫描 PDF、图像理解、完整多轮上下文与精确科学绘图不在当前功能验证范围内。

功能与协议说明见 [技术架构与实现](DEVELOPMENT.md) 和 [API 接口](API.md)。

### 本机验收流程

1. 更新后 `/api/health` 应返回 `0.7.0`，旧论文及原有阅读进度仍可打开。
2. 上传一篇文字 PDF，在“入库记录”观察阶段，成功后关闭窗口查看文献；再次上传同一文件不重复入库。
3. 在 PDF 第 2 页点击“记录当前页”，保存摘录、笔记与标签；关闭后从“阅读笔记”搜索并跳回第 2 页。
4. 创建问答并追问“它的局限是什么”；刷新、重新连接，在“问答记录”打开，确认回答与引用均保留。
5. 生成中关闭页面后重新连接查看记录；后台重启后的未完成草稿必须标为中断，不得当作成功答案。
6. 选两篇论文生成对比，逐项打开每篇原文；添加人工笔记，确认 AI 原始内容仍可见，导出文件包含状态与页码。
7. 翻译一页；保存一个新术语后重新提交相同页，确认新任务使用新版本，旧记录仍保留原译文。该步骤会产生真实模型调用。
8. 使用两个对应不同用户标识的令牌验证相互看不到论文、笔记、会话、术语或分析记录。
9. 使用临时测试论文验证删除提示及级联清理；不要用唯一原件做删除试验。
10. 在正常窗口及手机宽度查看新增按钮、笔记窗口、对比表横向滚动、键盘焦点与关闭行为。对比结果的语义正确性需人工对照原文。

上述流程是待本机执行的验收清单，不是已经完成的真实浏览器测试记录。
