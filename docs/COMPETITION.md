# 比赛材料准备清单（根据所附要求）

本文件是后续材料编写框架，不是已经完成的技术 PDF 或演示视频。所有“结果”和团队信息都需实际补齐。

## 代码仓库

- 保留现有 GitHub/Gitee 仓库和真实 Git 历史，设为 Public 或提供评审访问权限。
- README 包含项目介绍、技术架构、安装运行、团队信息。
- 提交依赖与 `.env.example`；不提交真实密钥、访问令牌、个人论文和数据库。
- 评审从新环境按 README 能启动；完成真实模型验收后锁定依赖版本。

## 技术文档 PDF（不超过 30 页，建议正文 18–22 页）

1. 项目概述（1–2 页）：学术资料分散、答案难核查的痛点，个人知识库场景。
2. 需求分析（2 页）：论文上传、持续积累、检索、问答、引用回溯、用户隔离。
3. 系统架构（3 页）：React/TS、FastAPI、PDF 解析、SQLite/Qdrant、模型层、数据流。
4. AI 技术方案（4 页）：BGE 选型依据、BM25/RRF、重排、DeepSeek 证据约束、参数选择和局限。
5. 核心实现（3 页）：入库状态、去重与 ID、混合候选合并、结构化引用、前端交互。
6. 测试与部署（3–4 页）：环境、功能与隔离测试、真实语料评测、失败案例、依赖和启动方式。
7. 创新与展望（2 页）：以可追溯阅读体验和持续积累为应用创新；说明工程优化及实测价值，勿将常见 RAG/RRF 组合宣称为原创算法。
8. 附录（1–2 页）：API、成员分工、参考资料和复现实验说明。

技术亮点需要证据：例如对比基线后混合召回改善了哪些问题、引用回溯如何减少核查成本。没有测量之前只写设计目标，不写准确率提升或低延迟结论。
