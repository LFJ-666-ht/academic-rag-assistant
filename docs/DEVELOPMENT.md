# 下一阶段开发与协作

## 这次合入方式

在已有仓库先查看 `git status`，保留或提交你们自己的未完成修改，然后建立功能分支：

```bash
git switch -c feat/persistent-rag-api
```

复制本包的新代码并比较合并配置；跑测试和本机真实模型验收后，用 PyCharm Git 界面逐项选中要提交的文件。不要选择 `.env`、`data/`、模型权重和论文原件。保留原有提交历史，不用重新建仓库。

建议按实际开发工作划分提交，例如“增加持久化知识库和去重”“修复混合检索候选融合”“增加问答引用接口”。如果这次将整包一次集成，可如实做一次集成提交，不拆造过去的开发记录。

没有提供 GitHub 地址/可操作 checkout，因此本次未执行 git push 或创建 PR。

## 并行分工建议（由团队执行）

| 负责人 | 本阶段任务 | 验收 |
|---|---|---|
| 后端/AI | 本机加载 BGE、配置 DeepSeek，完成两篇真实论文闭环 | 重启、删除、去重和引用页码正确 |
| 前端 | React + TypeScript：论文侧栏、上传、问答区、证据卡、PDF 预览 | 从后端拿真实数据，完整错误/加载状态 |
| 测试/文档 | 组织评测题、记录结果、完善技术文档和演示脚本 | 数据来自实际测试，章节对应代码 |

## 推荐优先级

P0：完成真实模型联调，再冻结 API 约定。至少选两篇你熟悉且有权用于演示的论文，分别测试单篇事实题、跨篇比较题、无答案题。

P1：React 前端与接口对接。先完成“上传 → 列表 → 提问 → 引用 → 原文”的闭环，再加动画、复杂主题等非关键功能。现有后端同步上传和非流式回答，UI 必须如实显示等待状态。

P2：建立至少 20 条人工标注问题（中文、英文、跨文献、证据不足各覆盖）。记录论文与页码、期望证据、是否召回、引用是否支持结论、响应时间。对比向量检索、混合检索、混合+重排的 Recall@k；记录答案证据支持率和无答案拒答率。不同方案必须同一语料和同一问题集，不预填提升百分比。

P3：按真实问题优化。段落/标题感知切分、重复片段去除、多语种 Embedding、PDF 版面解析、OCR、混合检索缓存。改 Embedding 需重建索引。拒答阈值必须从验证集校准，不能随意将 reranker 原始分数当置信度。

P4：需要上线时做正式账户认证、上传任务队列、网关限流和体积上限、配额、访问日志脱敏、HTTPS、Qdrant 服务模式、数据库迁移与备份。当前单进程本地数据模式是开发起点，不是多人公网生产部署方案。
