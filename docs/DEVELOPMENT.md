# 技术架构与实现

研迹 PaperTrail 采用 React 客户端与 FastAPI 服务端分离的结构。文献解析、检索、来源校验和数据访问由服务端执行；客户端承担文献选择、流式内容展示、PDF 阅读与进度管理、双语对照与配图交互。

## 系统组成

```mermaid
flowchart TD
    UI["React 文献工作台"] --> API["FastAPI 认证与接口"]
    API --> KB["PDF 解析与持久化知识库"]
    KB --> R["向量与关键词检索、融合、重排"]
    R --> T["DeepSeek 文本生成"]
    T --> UI
    API --> P["逐页原文提取与翻译队列"]
    P --> T
    P --> D["SQLite 翻译记录与缓存"]
    API --> I["Seedream 图片任务"]
    I --> UI
```

论文配图先通过检索和 DeepSeek 生成可编辑描述，客户端展示来源片段；用户确认后，才创建 Seedream 图片任务。

## 文献入库

PyMuPDF 按 PDF 物理页提取文本，分块在单页内部进行，保留文件名与页码。默认块长为 700 个字符，相邻块重叠 100 个字符。文档以 UUID 标识，以文件 SHA-256 在同一用户范围内识别重复上传。

SQLite 保存文档元数据和原文片段，本地 Qdrant 保存向量，文件系统保存原始 PDF。用户标识参与查询与权限校验，删除文档时同步移除原件、片段及对应向量。

单篇文件上限为 30 MiB、500 页、10000 个分块。没有可提取文本的 PDF 返回处理提示；系统不会将扫描图片当作已解析文本。

## 混合检索与引用问答

1. 根据访问令牌与文献选择确定检索范围。
2. BGE 计算问题向量并召回语义相近的片段；BM25 对分词后的文本进行关键词检索。
3. RRF 合并两路候选排序，BGE Reranker 对问题与候选片段进行重排。
4. 将选中的原文片段构造成带编号的证据，交由 DeepSeek 生成回答。
5. 服务端检查回答引用的编号是否存在于本次证据集合，再返回引用片段与 PDF 页码。

默认 Embedding 为 `BAAI/bge-small-zh-v1.5`，Reranker 为 `BAAI/bge-reranker-base`，均按需加载。问答接口默认选择最多 10 条证据，`top_k` 可配置为 1–30。没有检索证据时不调用文本模型。

模型提示词约束回答以证据为依据，并将文献文本视为资料而非可执行指令。引用编号有效仅表示来源编号合法；系统未实现对所有论断的自动事实验证。当前检索方案属于现有方法的工程集成，尚未提供相对单一检索基线的量化性能结论。

## 流式回答与异常状态

后端读取模型平台的流式响应，再通过 NDJSON 向客户端发送 `progress`、`delta`、`done` 或 `error` 事件。进度信息不包含模型内部思考正文；`delta` 阶段的内容是未完成引用校验的草稿。

回答达到长度上限或模型连接中断时，已有正文在完成引用编号检查后可以作为不完整结果保留，并携带 `finish_reason`、`incomplete` 和提示信息。未知引用编号会触发错误。浏览器未收到 `done` 时，不将草稿标记为已完成回答。

文本生成的输出预算与超时由后端配置控制；配图描述使用独立预算。模型调用失败后不会自动创建第二次收费请求。详细协议见 [API 接口](API.md)。

## 本地阅读进度

`metadata.sqlite3` 新增 `reading_progress` 表，以文献 UUID 为主键并通过外键关联文献，删除级联清理。启动使用 `CREATE TABLE IF NOT EXISTS` 增量创建，旧库中已有论文与索引保持兼容。阅读状态与入库状态使用不同字段。

服务端所有读取与写入先检查文献所有者，并复用知识库锁与 SQLite 事务。`last_page` 记录继续阅读位置，`furthest_page` 单调记录最远位置；只有显式重置待读会归零。完成状态由用户指定，不能用浏览最后一页推断。记录时间采用 UTC ISO 格式，前端按本地时间显示。

PDF 页面渲染成功后才记录页码；缩放与同页重绘不重复保存。`ReadingSaver` 串行发送页码变更并合并等待中的翻页，防止慢响应导致上次页码回退到旧请求。正常关闭等待保存完成，失败时明确提示重试或不保存关闭。记录不调用 BGE、DeepSeek 或 Seedream，既不消耗模型额度，也不依赖模型服务在线。

## 逐页翻译与来源追踪

翻译从保存的 PDF 直接提取所选页面的完整文本，并记录论文 UUID、文件名和物理页码。不通过 top-k 检索片段构建全文，也不拼接存在重叠的分块。每页按最多 1800 字符分段，优先在换行或句尾切分，各段不重叠且不丢弃源字符。

后台单线程依次翻译各段，复用 DeepSeek 认证与地址，独立输出预算默认 8192 token。已识别的方舟型号关闭翻译任务的深度思考；未知模型不附加方舟专用参数。翻译单段读取超时最多 90 秒，响应处理的累计时间检查上限为 180 秒；网络读取本身仍受读取超时约束。这些是工程限制，不代表平台模型能力上限。

只有一页的所有段落均返回正常完成标记时，才原子保存该页译文及缓存。任务与完成页在 `translations.sqlite3` 持久化，缓存键区分用户、文献、页码、语言、模型、服务地址、术语内容版本及原文哈希。重试可复用完整页面；不完整页面不会存入缓存。提示词要求忠实翻译并保留术语、数字与引用编号，但不等同于译文质量已自动核验。

模型请求期间不持有数据库锁。涉及知识库与翻译存储时统一先获取知识库锁，随后获取翻译锁；删除论文与提交译文遵循同一顺序，避免删除后的任务写回。任务取消或后端重启不自动发起新的收费请求。前端只轮询本地任务，提交确认不明确时保留原请求编号。

当前追踪范围是用户上传文献及其阅读状态、阅读页码、来源证据和翻译记录；不包含外部学术网站自动订阅、爬取或论文更新推送。

## 图片任务与存储

Seedream 根据确认后的描述生成单张 2K 图片。响应使用 Base64 图片数据，服务端校验文件格式和大小后保存；客户端通过带认证的文件接口获取预览及下载内容。

任务状态为 `queued`、`running`、`succeeded` 和 `failed`，并记录请求编号、模型、时间、错误与来源快照。同一用户、同一请求编号和相同参数复用已有任务；使用相同编号但改变参数会被拒绝。

图片队列由单个工作线程处理，每个用户最多保留 1 个未完成任务，服务端最多接受 8 个未完成任务。状态轮询读取本地记录，不会再次调用图片模型。重启时遗留的未完成任务被标记为失败，系统不自动重新生成。

图片列表展示最近 30 条任务，这不是持久化存储上限。当前没有图片自动过期清理或删除界面；删除来源论文不会自动删除已有图片及其来源快照。

## 运行与数据边界

服务采用单后端进程，本地 Qdrant 数据目录不能由多个实例同时打开。备份应在停止后端后复制整个数据目录，避免只备份向量或只备份 PDF 造成数据不一致。

项目访问令牌与模型平台密钥分开管理，模型密钥保存在服务端配置中。当前没有完整账号注册、生产级用量配额或分布式任务调度；公网部署与高并发容量未纳入现有验证结果。安装、数据迁移与故障处理见 [安装与使用](USAGE.md)。

## 代码规范与质量检查

源文件采用 UTF-8、LF 换行和文件末尾换行；Python 使用 4 空格缩进，TypeScript、JSON 与样式文件使用 2 空格。`.editorconfig` 约束编辑器行为，`.gitattributes` 统一 Git 中文本文件的换行方式。

Python 命名采用函数/变量 `snake_case`、类 `PascalCase`、常量 `UPPER_SNAKE_CASE`。Ruff 配置在 `pyproject.toml`，检查导入顺序、未使用符号与基础错误，并以 100 列为目标格式化代码。关键注释解释约束和原因，例如引用不得跨页、用户隔离边界及收费请求不自动重试，避免仅复述语句。

TypeScript 启用 `strict`；组件和类型使用 `PascalCase`，函数及变量使用 `camelCase`。`npm run build` 先执行 TypeScript 类型检查再打包。新增功能沿用 `api.ts` 请求封装及已有错误类型，不将模型平台密钥写入前端。

项目根目录执行 Python 检查：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m pytest -q
```

需要整理 Python 格式时执行 `python -m ruff format .`，然后审查差异并重跑检查。公共测试资源位于 `tests/helpers.py`，知识库 fixture 由 `tests/conftest.py` 提供；测试模块不互相导入。

前端检查：

```powershell
cd frontend
npm ci
npm test
npm run build
```

`.github/workflows/ci.yml` 对后端配置了 Python 3.12 的 Linux/Windows 检查，对前端配置了 Node.js 24 的测试和构建。工作流使用模拟模型与临时目录，不需要平台密钥或真实 BGE 权重。云端是否执行成功以对应提交的 Actions 记录为准。

## 持久化问答与研究任务

问答请求使用客户端 UUID 去重。同一个 UUID、同一问题及参数返回已有状态；冲突参数拒绝。后台线程消费模型流并将草稿节流写入 SQLite，完成后保存经过引用编号校验的结果。NDJSON 连接只读取持久化记录，浏览器断线不重新发起模型调用。每个用户仅有一个进行中的问答，全服务最多接受四个，两个工作线程；会话列表按更新时间排序。

会话固定论文集合，最多 100 篇。历史仅选最多四条已完成、非截断且有合法引用的问答，每条问题最多 1000 字符、回答最多 2000 字符，并移除历史引用编号。检索查询加入最近两条问题的主题，新回答提示明确历史不是证据。该方式是有界上下文，不是全文长记忆。

结构化分析每篇围绕五个维度各检索最多三个片段，按 chunk UUID 去重。每篇独立调用模型并校验 JSON 字段及来源编号范围；描述非空但没有引用、引用越界或输出截断会使该篇失败。对比表展示已完成卡片，缺少资料的字段显式留空说明。AI 结果与人工 edits 分开存储，修订号防止多窗口覆盖。

入库与分析各使用一个工作线程，各队列全服务最多四个未完成任务、每用户一个。入库阶段回调写入独立任务库，状态查询不获取知识库锁，因此模型编码过程中仍能读取阶段。持久化任务状态并不等于支持中断续跑：入库数据接收后暂存进程内，进程退出将未完成任务标记中断，下次手动重传按哈希去重。

涉及多库锁时遵循 `kb.lock → tasks.lock/research.lock/translation.lock`；模型调用期间释放存储锁，知识库入库编码仍沿用原有互斥锁。论文删除和分析写回统一获取知识库锁，已删除任务不能被模型迟到响应重新写回。关闭服务先等待工作线程，再关闭数据库。

术语表按用户和目标语言隔离，内容排序、去重后以 SHA-256 标识版本；修订号用于编辑冲突检查。任务持久化快照，同 UUID 的确认优先匹配原任务版本；新任务校验当前版本。非空术语表把内容指纹加入翻译缓存身份；空术语表继续兼容旧版缓存。

`research.sqlite3` 和 `tasks.sqlite3` 使用 WAL；数据库备份应在服务完全停止后进行。新增翻译列采用增量迁移；降级需一并恢复原数据快照，不能只回退源码。
