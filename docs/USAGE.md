# 安装与使用

v0.4.1 · Windows / PowerShell

本指南说明环境配置、模型准备、文献问答、论文翻译、概念配图、数据迁移与故障处理。首次运行按第 1–4 节配置；功能操作见第 5–6 节（翻译见 5.1 节，阅读进度见 5.2 节）；数据迁移、排错与测试见第 7–9 节。

## 1. 环境与代码

参考环境为 Python 3.12（64 位）、Git 和 Node.js 24+，可选用 PyCharm 作为开发环境。以下命令适用于 Windows PowerShell。

首次获取代码时，在选定的工作目录执行：

```powershell
git clone https://github.com/LFJ-666-ht/academic-rag-assistant.git rag-academic-assistant
cd rag-academic-assistant
```

已有代码时直接进入项目根目录，即包含 `run_backend.py` 和 `requirements.txt` 的目录。创建 Python 环境并安装运行依赖：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

PyCharm 解释器选择本项目的 `.venv\Scripts\python.exe`。已经跑通的电脑不重建环境；旧电脑的 `.venv` 不能直接复制到新电脑使用。`requirements-test.txt` 供轻量测试，`requirements-tested.txt` 是历史版本记录，二者都不能代替运行依赖。

依赖文件用途：

| 文件 | 用途 |
|---|---|
| `requirements.txt` | 后端运行依赖，包含本地 BGE、模型下载、PDF、存储与接口库 |
| `requirements-test.txt` | 使用模拟 BGE 的轻量测试，不安装真实模型运行栈 |
| `requirements-dev.txt` | 轻量测试依赖加 Ruff 规范检查工具 |
| `requirements-tested.txt` | 历史测试环境的直接依赖版本记录，不是完整锁文件 |
| `frontend/package.json`、`frontend/package-lock.json` | 前端依赖声明与锁文件，通过 `npm ci` 安装 |

## 2. 创建配置与项目访问令牌

仓库提供 `.env.example` 配置模板，真实密钥不随源码分发。在项目根目录创建本地配置：

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

只有不存在时才复制；已有 `.env` 直接保留。文件与 `run_backend.py` 同级，不能叫 `.env.txt`。只修改 `.env.example` 不会生效。

没有可用令牌时生成：

```powershell
.\.venv\Scripts\python.exe -c "import secrets,json; print('API_TOKENS_JSON=' + json.dumps({secrets.token_urlsafe(32): 'demo-user'}))"
```

**把打印出的整行复制到 `.env`，替换同名行并保存。命令只打印，不会自动写文件。** 冒号左边是至少 16 位随机令牌，右边是用户标识；使用英文双引号，不重复添加配置行。迁移旧数据时保留原用户标识。

模板中的 `{}` 故意不提供可用的公共令牌；未生成并填写自己的令牌时，后端会拒绝启动。已经配置好的 `.env` 不需要用新模板覆盖。

### 2.1 环境变量说明

所有应用配置放在项目根目录 `.env`。启动器先切换到项目根目录，再加载配置；终端或 PyCharm 已设置的同名环境变量优先于 `.env`。下表中的默认值来自当前代码，模型可用范围以实际服务平台为准。

| 变量 | 默认值 / 填写要求 | 作用 |
|---|---|---|
| `API_TOKENS_JSON` | 必填非空 JSON 映射；令牌至少 16 位 | 令牌映射到用户标识，决定数据访问范围 |
| `DEEPSEEK_API_KEY` | 文本服务真实密钥 | 文献问答、论文翻译与配图描述认证 |
| `DEEPSEEK_MODEL` | 文本服务已开通的模型 ID | 不附加 `L=` 等前缀 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | OpenAI 兼容接口的基础地址，需与密钥及模型匹配 |
| `DEEPSEEK_MAX_TOKENS` | `auto` 或正整数 | 已识别方舟模型使用代码预设；其他型号使用平台默认 |
| `DEEPSEEK_TOKEN_PARAMETER` | `max_tokens` | 可改为平台要求的 `max_completion_tokens`，仅发送一项 |
| `DEEPSEEK_REASONING_EFFORT` | `auto` | 可填 `none/minimal/low/medium/high/max`，需平台支持 |
| `DEEPSEEK_THINKING` | `auto` | 可填 `enabled/disabled`，需平台支持 |
| `DEEPSEEK_TIMEOUT_SECONDS` | `300` | 上游读取空闲超时，单位秒，正整数 |
| `DEEPSEEK_TOTAL_TIMEOUT_SECONDS` | `7200` | 总生成期限，单位秒；收到新块时检查 |
| `DEEPSEEK_TRANSLATION_MAX_TOKENS` | `8192`，可省略 | 每段翻译的独立输出预算；按平台支持的上限设置 |
| `DEEPSEEK_IMAGE_PROMPT_MAX_TOKENS` | `4096` | 配图描述任务的独立输出预算 |
| `SEEDREAM_API_KEY` | 可选，启用图片生成时填写 | 图片模型密钥，留空时停用生成能力 |
| `SEEDREAM_MODEL` | `doubao-seedream-4-0-20260415` | 对应账号已开通的图片模型 ID |
| `SEEDREAM_BASE_URL` | `https://ark.cn-beijing.volces.com/api/v3` | 图片服务基础地址 |
| `DATA_DIR` | `./data` | PDF、SQLite、Qdrant 与图片的持久化目录 |
| `EMBEDDING_MODEL` | `BAAI/bge-small-zh-v1.5` | 模型 ID 或本地目录；与已有索引配置保持一致 |
| `RERANKER_MODEL` | `BAAI/bge-reranker-base` | 重排模型 ID 或本地目录 |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 允许的浏览器来源，以逗号分隔、不加空格 |
| `HF_ENDPOINT` | 可选，通常使用官方源 | 模型下载地址；`prepare_models.py --endpoint` 显式参数优先 |
| `SENTENCE_TRANSFORMERS_HOME` | 可选，如 `./model_cache` | 下载与加载共用的缓存位置，两个阶段保持一致 |

`run_backend.py` 将当前后端进程的 `HF_HUB_OFFLINE` 和 `TRANSFORMERS_OFFLINE` 设为 `1`；准备脚本在下载时改为联网、检查时改为离线。通常不需要把这两项另写进 `.env`。DeepSeek 和 Seedream 的 HTTP 客户端不读取系统代理环境变量，模型下载脚本的代理设置与它们相互独立。

## 3. 模型服务配置

DeepSeek 负责文献问答、论文翻译与配图描述，Seedream 负责图片生成。两组配置相互独立；已有可用文本服务时，可保留其配置并按需启用配图。

| 配置项 | 填写内容 |
|---|---|
| `DEEPSEEK_API_KEY` | 文本模型服务平台的真实密钥 |
| `DEEPSEEK_MODEL` | 同一平台为账号开通的完整模型 ID，不要带多余的 `L=` |
| `DEEPSEEK_BASE_URL` | 文本服务地址；保留原来已经跑通的值 |
| `SEEDREAM_API_KEY` | 有 Seedream 权限的火山方舟 API Key |
| `SEEDREAM_MODEL` | `doubao-seedream-4-0-20260415` |
| `SEEDREAM_BASE_URL` | `https://ark.cn-beijing.volces.com/api/v3` |

Seedream 示例使用已完成单次接口验证的型号。使用前需确认模型对当前平台账号及密钥可用，在根目录 `.env` 配置：

```dotenv
SEEDREAM_API_KEY=替换为具备模型权限的API密钥
SEEDREAM_MODEL=doubao-seedream-4-0-20260415
SEEDREAM_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
```

把第一行的中文占位值完全替换掉。地址只写到 `/api/v3`，不要再追加 `/images/generations`。同名配置已有就改原行，不重复追加。DeepSeek 若也来自同一方舟项目且密钥有两个模型权限，可以两处填写同一密钥；来自不同平台时各填各的密钥和地址。

### 3.1 DeepSeek V4.1 Flash 261017 长回答配置

以下展示项目对方舟 `deepseek-v4-1-flash-261017` 的配置预设；适用性取决于实际平台和账号。保留已有 API 密钥，在根目录 `.env` 修改同名项：

```dotenv
DEEPSEEK_MODEL=deepseek-v4-1-flash-261017
DEEPSEEK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
DEEPSEEK_MAX_TOKENS=393216
DEEPSEEK_TOKEN_PARAMETER=max_tokens
DEEPSEEK_REASONING_EFFORT=max
DEEPSEEK_THINKING=enabled
DEEPSEEK_TIMEOUT_SECONDS=300
DEEPSEEK_TOTAL_TIMEOUT_SECONDS=7200
DEEPSEEK_IMAGE_PROMPT_MAX_TOKENS=4096
```

`393216 = 384 × 1024` 是当前代码的请求预算预设，不代表已经验证平台能够完成该长度的输出。预算不是目标回答长度，token 也不等于字数；实际支持范围及推理选项由所用平台决定。较大的预算和推理强度可能增加响应时间与用量，应结合平台限制和任务需求设置。配置变化后需重启后端。

代码默认只在明确识别到方舟域名及型号时应用对应预设：261017 为 384K / max，260910 为 128K / max。显式配置优先。其他平台、其他型号或 `ep-...` 推理接入点不猜测能力，`auto` 使用平台默认；应按该接入点实际模型填写参数。`max_tokens` 和 `max_completion_tokens` 不会同时发送。若平台返回参数错误，应核对控制台当前的接口限制，程序不会自动重试或更换模型。

上游使用流式请求，网页显示检索、思考状态和正文草稿；正文完成后再校验引用编号。不会向前端返回模型内部思考文本。默认单次上游读取空闲超时 300 秒，前端空闲等待 360 秒，持续收到内容会刷新空闲计时。后端总生成期限默认 7200 秒，在收到新块时检查；阻塞读取仍受空闲超时约束。公网部署的网关也需关闭响应缓冲，并配置足够的读取超时。

达到输出/上下文上限或上游断线且已有正文时，返回未完成标记和已校验的引用；没有正文时返回具体错误。浏览器到后端断线时只能保留未校验草稿，不能当成完整答案。不会自动重新发起收费请求。关闭页面或中止等待不保证平台立即停止计费，重新提交前应检查平台记录。

配图描述独立使用 4096 token 预算；已识别的 V4.1 模型关闭该短任务的深度思考。Seedream 参数不受文本回答预算影响。

**能力范围：** 问答检索默认 10 条、可选最多 30 条片段。更大输出预算不会自动把整篇论文或全部论文送入模型；连续追问使用最多 4 条已完成的近期对话辅助理解，但每轮重新检索；当前未接入 PDF 图片理解或百万 token 全文分析。

配置实现见 `backend/generation.py`，测试覆盖范围见 [测试与验证](VALIDATION.md)。自动化测试验证请求字段构造，不验证真实模型的最大输出能力。

网页“连接知识库”填写的是 **`API_TOKENS_JSON` 中冒号左侧的随机令牌**，不带引号。两个模型密钥只放后端 `.env`，不写进 React，不创建前端密钥文件。没有配置 Seedream 时问答仍可用。

不打印密钥的检查命令：

```powershell
.\.venv\Scripts\python.exe -c "import json; from dotenv import dotenv_values; d=dotenv_values('.env'); t=json.loads(d.get('API_TOKENS_JSON') or '{}'); print('token_valid:',isinstance(t,dict) and bool(t) and all(isinstance(k,str) and len(k)>=16 and isinstance(v,str) and bool(v.strip()) for k,v in t.items())); print('text_key_set:',bool(d.get('DEEPSEEK_API_KEY'))); print('image_key_set:',bool(d.get('SEEDREAM_API_KEY')))"
```

这只检查配置是否存在，不证明密钥有效或账号有权限。配置修改后重启后端。

## 4. 准备本地模型并启动

默认 Embedding 为 `BAAI/bge-small-zh-v1.5`，Reranker 为 `BAAI/bge-reranker-base`。新电脑没有缓存时，在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe prepare_models.py --endpoint https://huggingface.co
```

如需使用镜像，可在确认来源与网络可用性后将地址替换为 `https://hf-mirror.com`。等待脚本完成下载和检查，出现 `Embedding OK: (1, 512)` 与 `Reranker OK: ...`。已有缓存时只需：

```powershell
.\.venv\Scripts\python.exe prepare_models.py --check-only
```

下载不完整时补齐完整模型缓存，不要随意改 Pooling 或 Embedding 模型来绕过错误。`run_backend.py` 设置本进程的 HF 离线模式，避免运行时重复联网下载；此设置不影响 DeepSeek/Seedream 的 HTTP 请求。

**终端一：后端**

```powershell
.\.venv\Scripts\python.exe run_backend.py
```

看到 `Application startup complete.` 后保持运行。健康检查 <http://127.0.0.1:8000/api/health> 应显示 `version: 0.4.1`，但不代表模型调用已成功。后端启动入口为根目录的 `run_backend.py`。

**终端二：前端**

```powershell
cd frontend
npm ci
npm run dev
```

`npm ci` 在首次安装或依赖变更时运行。平时只运行 `npm run dev`。打开 <http://127.0.0.1:5173/>，连接知识库。前端默认将 `/api` 转发到 8000 端口，不需要额外前端 `.env`。

只有一个后端进程可以使用同一份本地 Qdrant 和图片任务目录，不设置多 worker，不同时运行两个后端。

## 5. 上传论文和引用问答

连续上传多篇有可提取文字的 PDF，等待解析和索引完成。单篇上限 30 MiB、500 页、10000 分块；同用户相同文件会去重。扫描版全无文字时需要先 OCR。

选择全部或指定论文后提问。回答中的引用可查看原文片段与 PDF 页码；页码是 PDF 物理页码，不一定等于论文印刷页码。引用编号通过检查不代表每个结论都正确，需结合原文核对。

也可通过 <http://127.0.0.1:8000/docs> 调试。先 Authorize 填项目令牌；按 `GET /api/documents`、`POST /api/documents`、`POST /api/search`、`POST /api/chat` 的顺序验证。搜索/聊天请求示例：

```json
{"question":"论文采用了什么方法？","top_k":5,"document_ids":null}
```

`null` 是全部自己的论文，空数组 `[]` 表示不选择论文；指定范围填真实文档 UUID。

### 5.1 论文翻译与原文对照

翻译沿用现有 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`；问答配置可用时无需申请另一把密钥。更新前后端后重启，右上角会出现“论文翻译”。现有 `.env` 不必替换；可选的 `DEEPSEEK_TRANSLATION_MAX_TOKENS` 默认 `8192`，表示每段输出预算，不是译文目标长度。

1. 上传含文字的 PDF。在文献列表点击该论文的“翻译”；也可先打开 PDF，翻到需要的页面，点击“翻译当前页”。
2. 选择目标语言“简体中文”或“英语”，填写起始页与结束页。这里的页码是 PDF 阅读器中的物理页码，不是论文印刷页码。当前页入口会把两个页码都预填为该页。
3. 先查看右侧起始页原文，再点击“开始翻译”。每次最多 50 页；超过 50 页的论文按 1–50、51–100 等范围分批处理。单页最多 2 万字符，单任务最多 20 万字符；超出时会拒绝，不会截断原文。
4. 查看进度；完成一页后可点击页码，在右侧对照原文与译文。译文按完整页面保存。关闭窗口不会停止任务，重新打开后从“翻译记录”查看。
5. 任务结束后可“导出双语 TXT”，或复制已完成页面的译文。导出保留论文名、PDF 页码、原文、译文与完成状态。部分失败的任务仅保留已完成页，其他页面明确标注“未完成”。

“停止后续翻译”会阻止后续页面/段落处理，已发送的平台请求可能仍会计费。失败后不自动重新调用模型；核对平台记录后，可点击“重新选择此范围”再开始。相同用户、文献、页面、目标语言、模型与服务地址的已完成译文会复用；未完成页重新翻译可能产生费用。提交确认超时可点击“重新确认提交”，使用相同请求编号查询或创建同一任务，避免因重复点击创建多个任务。

翻译记录保存在 `DATA_DIR/translations.sqlite3`，重启后仍可查看。删除论文时，其翻译记录与缓存也一并删除。当前列表展示最近 50 条任务，没有自动过期清理。每个用户最多 1 个未完成任务，全服务最多排队 4 个，单工作线程顺序翻译。

翻译原文直接来自 PDF 页面，不拼接问答用的重叠检索片段。长页面分段交给模型，不代表模型一次读完整篇论文。扫描页没有 OCR 时无法翻译；混合 PDF 的空文本页会跳过。双栏、图表、上下标与公式提取可能失序或丢失格式，系统不重建 PDF 原版式。AI 译文只供辅助阅读，术语、数据和结论应对照原文核验。

### 5.2 本地阅读进度管理

入口在左侧“我的文献”，问答范围下方的“阅读进度”。手机窄屏需先点击“展开文献列表”。每篇论文都有阅读状态、上次页码、进度条、“开始阅读/继续阅读”和“记录页码”。无需调用文本或图像模型。

1. 点击“开始阅读”或论文名称，打开 PDF；页面成功显示后自动保存页码，状态由“待读”变成“在读”。阅读器工具栏下方显示保存结果。
2. 正常关闭阅读器会等待已排队的页码保存；若保存失败，可“重试保存”，也可明确选择“不保存并关闭”。保存成功前直接刷新网页或关闭浏览器，最后一次页码可能尚未写入。
3. 下次点击“继续阅读”回到上次页码；从回答引用进入时仍打开引用所在页，并把实际显示的页面记为新的上次位置。
4. 论文卡片上的状态下拉框可改为“在读”或“已读”。“已读”是手动确认；浏览到最后一页不会自动标记完成。已读论文重新打开时保持已读。
5. 在其他 PDF 软件中阅读后，可点击“记录页码”手动保存位置。系统无法监控外部阅读器，只有项目内阅读器自动记录。
6. 点击“全部/待读/在读/已读”筛选文献，并可配合名称搜索。筛选只影响文献列表，不改变问答范围或已经选择的论文。
7. 要重新开始阅读，可改为“待读”并确认重置；这会清除上次页码、最远页码和完成时间。论文原文与译文保留。

进度条按“最远翻阅页码 ÷ PDF 总页数”计算，往回翻页不会降低进度。跳页不代表中间页面都已阅读，因此它是页码进度，不是理解程度或实际逐页完成率。“上次页码”用于继续阅读，与“最远页码”分别保存。

数据保存在现有 `DATA_DIR/metadata.sqlite3` 的 `reading_progress` 表中。首次运行新版会自动创建表，原有论文默认“待读”，不需要删除数据库或重新上传。相同用户重复上传同一论文保留进度；删除论文同时删除该论文的阅读记录。换电脑需复制整个数据目录并保持访问令牌对应的用户标识一致。

## 6. DeepSeek + Seedream 配图

- **直接描述：** 右上角“AI 配图”→输入画面描述→Seedream 生成一张 2K 图片。
- **根据论文：** “AI 配图”→“根据论文”→选择论文和主题→DeepSeek 整理描述→检查原文、修改草稿→Seedream 出图。
- **从回答开始：** 点击回答下方“生成配图”，带入问题与相关论文范围，再整理草稿。

DeepSeek 的草稿基于重新检索到的最多 5 个片段，不是发送全文。点击 Seedream 生成按钮前不会调用图片模型；文本草稿和图片分别消耗对应平台额度。DeepSeek 剩余 token 不代表还有图片额度。

生成状态包括排队中、生成中、成功、失败。关闭窗口后，已受理任务继续；同一用户重新打开可查看最近 30 条、预览和下载。每个用户最多同时处理一张，服务器队列上限 8 个。轮询只查本地状态，不会反复调用 Seedream。

网络中断后若出现“提交结果尚未确认”，使用“确认提交状态”复用同一任务编号。平台调用超时或后端停止时不要连续新建任务，先查看平台调用记录；程序不会自动重试图片生成。

图片适合作概念配图和报告插画，不代替精确数据图或实验结果。文字、结构和学术含义需人工检查。当前版本没有图生图、组图或图片删除界面；最近 30 条只是显示窗口，文件不会自动过期。论文删除也不会自动删除已保存图片的来源片段快照。

## 7. 数据迁移与备份

1. 在新电脑获取与原环境匹配的代码版本，重新创建 `.venv` 并安装前后端依赖。
2. 安全复制根目录 `.env`，保留用户标识和 Embedding 模型设置；不要通过公开 Git 传密钥。
3. 停止旧后端，将整个 `DATA_DIR`（默认 `data/`）复制过去，包括 PDFs、SQLite（含 `translations.sqlite3`）、Qdrant 和 `images/`。不要只复制 PDF、只复制向量或把两份现有库直接混合。
4. 重新下载 BGE，或复制完整 Hugging Face 缓存（保留 refs/snapshots/blobs 等结构），再运行 `--check-only`。
5. 用同一用户标识启动检查列表、检索、引用和图片历史。两台机器各自新增的数据不会通过 Git 自动同步。

## 8. 常见问题

| 问题 | 处理 |
|---|---|
| `API_TOKENS_JSON` 非空映射报错 | 检查是否真的创建根目录 `.env`、是否粘贴了完整配置行、是否英文双引号和令牌至少 16 位 |
| 配置正确但仍用旧值 | 查看 PyCharm/当前终端是否有同名环境变量覆盖；可移除当前 PowerShell 的 `Env:API_TOKENS_JSON` 后重启，勿打印密钥 |
| 模型下载卡住/离线加载失败 | 单独运行 `prepare_models.py --check-only` 查看缺失；确认网络或完整缓存，不重复启动多个后端 |
| 模型不存在、HTTP 404 | 核对对应平台的地址、模型 ID、开通状态；检查 ID 前是否误加 `L=` |
| 401/403/配图无权限 | 区分项目令牌与平台密钥；平台权限错误到服务商核对 |
| 配图接口不存在 | 检查运行版本与 API 路径，确认从项目根目录通过 `run_backend.py` 启动 |
| 没看到阅读进度 | 确认前后端均已更新为 v0.7.0，重新启动并刷新；入口在左侧“我的文献”，窄屏先展开列表 |
| 阅读进度未保存 | 保持后端运行并检查项目访问令牌；在 PDF 中点击“重试保存”。不能把尚未保存的提示当成成功 |
| 翻译入口未出现 | 同时更新前后端，重启两个终端并刷新网页；后端 `/api/health` 版本应为 `0.7.0` |
| 翻译服务未启用 | 检查已有的 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 并重启后端，不需要新的翻译密钥 |
| 翻译被截断或超时 | 已完成页保留；核对平台记录和单段输出上限后手动重试，系统不会把部分译文当成完整页 |
| 翻译提示无文本 | 检查 PDF 能否选中文字；扫描页先进行 OCR |
| 配图尚未配置 | 填写 SEEDREAM 三项并重启；普通问答仍可用 |
| 配额或频率受限 | 核对图片模型额度和限流，不能用文本 token 余额判断 |
| 自动刷新暂停 | 检查后端/网络，点击刷新；不要反复重新生成图片 |
| 图片完成但无法预览 | 点击重新读取，检查 `data/images/` 文件是否仍存在 |
| 看不到旧论文/图片 | 检查 DATA_DIR 是否正确，以及令牌映射的用户标识是否与原来一致 |
| Qdrant 被占用 | 停止另一个使用相同数据目录的后端实例，等待退出后再启动；保留数据库与锁文件 |

## 10. 问答记录、笔记与研究整理（v0.7.0）

### 问答记录与连续追问

在工作台发送问题后会创建持久化会话。“问答记录”支持重新打开、搜索、重命名和删除；“新问答”开始另一段会话，不会删除旧记录。刷新后需要重新输入项目访问令牌，再从问答记录进入。令牌仍只保存在页面内存。

每段会话固定创建时的论文范围；改变选择范围后发送问题，会新建会话，避免旧问题与新论文混用。续问每轮重新检索，最多带入 4 条已完成且有有效引用编号的近期问答，并限制历史文本长度。历史引用编号不会直接沿用到新回答；不能将此功能理解为模型始终记得整篇论文或所有历史。

关闭页面或网络断开不自动重发模型请求，后台已接受的问答可继续保存。重新打开记录时，进行中的回答会只读轮询；如果后端重启，未完成任务会标记中断，并保留已落盘草稿。草稿没有完成引用校验，不能作为完整答案使用。停止后端前等待任务完成。

删除论文会使旧会话中该论文原文不可打开；历史回答保留。包含已删除论文的会话不能直接继续追问，应新建并选择有效文献。删除会话不删除文献或笔记。

### 阅读笔记、摘录、书签与标签

入口为文献区“阅读笔记”、每篇论文的“笔记”，以及 PDF 阅读器的“记录当前页”。阅读器先保存页码，再切换笔记窗口。

- 选择论文、PDF 物理页码和“阅读笔记”或“页码书签”。书签允许不填正文，笔记需填写内容。
- 可粘贴摘录，并用逗号分隔最多 10 个标签；“查看本页可复制原文”便于复制文本。
- 已保存记录可按论文、文字或标签筛选，打开对应原文、编辑或删除；支持导出 TXT。
- 修改冲突会提示重新载入，不会悄悄覆盖其他窗口的新内容。笔记和摘录由用户记录，不做自动真实性判定。

当前实现是按页关联的笔记与书签，不包含 PDF 选区高亮或批注文件写回。保存笔记不调用模型。

### 阅读卡片与 2–5 篇论文对比

点击“阅读卡片 / 对比”，展开选择论文。选择 1 篇生成卡片，2–5 篇生成统一维度对比表。每篇分别围绕研究问题、方法、数据、结论与局限检索后调用文本模型，避免一篇论文占满所有检索名额。

展开各项“原文依据”查看片段，或跳转 PDF。缺乏依据的字段显示“未找到相关说明”，这不代表原文没有该内容。卡片基于检索片段，不等于完整全文精读或系统综述。

“编辑人工笔记”保存独立的人为修改，AI 原始结果及来源保持可核查；人工补充显示“未自动验证”。停止任务后保留已完成论文的卡片，当前尚未完成的卡片不作为完整结果入库。每篇生成会调用一次文本模型；重新生成属于新的收费请求。

记录窗口显示最近 50 条任务，可导出卡片和原文 TXT。删除论文会删除包含它的整组分析记录，因此需要时先导出；已有问答历史不随之删除。

### 翻译术语表

在论文翻译窗口选择目标语言，展开“翻译术语表”，每行填写 `原词=译法`，例如 `responsivity=响应度`，点击“保存术语表”后再开始翻译。中文与英文目标各自维护术语表，最多 100 个词。

翻译任务保存提交时的术语快照与版本。术语变化后，新任务不会错误复用其他版本的页面缓存；旧记录显示原版本，必要时提示“当前术语表已更新”。术语完全相同且其余条件相同时可复用已完成页。模型仍可能误译，术语、公式与数字需对照核验。

### 入库阶段与恢复

新上传接口接收文件后返回后台任务，界面依次显示实际解析、计算向量及写入索引的阶段。分块计数是已处理的批次进度，不是估计的完成时间。首次加载本地模型时可能长时间停留在向量计算阶段。

“入库记录”可查看最近 50 个任务，重新连接后仍可读；关闭此窗口会刷新文献列表。上传传输本身不支持断点续传。后端中断时不会自动重新入库；检查现有文献后再上传相同文件，同一用户按文件哈希去重。

### 数据备份、升级与降级

新增 `DATA_DIR/research.sqlite3` 保存笔记、会话和术语表，`tasks.sqlite3` 保存入库与卡片任务；原有翻译库增加术语快照字段。正常升级自动增量建表和加列，不要求删除原有论文或索引，也不需要新增模型密钥。

升级前停止前后端并备份整个 `DATA_DIR`。更新包安装器同时备份待变更源码与当前数据目录；自定义数据位置时显式传入 `--data-dir`。不能只把旧版 `translations.py` 换回去降级：旧版按固定列数写入，无法写入已升级的翻译表。需要降级时必须停止服务，恢复同一次备份中的源码和完整数据目录；升级之后的新记录不会存在于升级前备份中，先导出需要的内容。

本地数据备份与 Git 源码提交分开；不提交 `.env`、`data`、模型权重、更新包或备份。详细质量评测见 [RAG 质量评测](EVALUATION.md)。
